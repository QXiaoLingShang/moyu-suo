# TypeScript、命名与注释

## 命名

- Astro 组件使用 `PascalCase.astro`；TypeScript 模块沿用当前 `camelCase.ts`；样式文件和 CSS 类使用 kebab-case。
- 变量与函数用 `camelCase`；类型、接口和类用 `PascalCase`；模块级固定键或枚举式常量可用 `UPPER_SNAKE_CASE`。
- 名称表达业务角色和状态，例如 `activeArticle`、`highlightDuration`；布尔值使用 `is`、`has`、`can` 等可读前缀。避免 `data`、`value`、`manager` 这类脱离上下文的万能名称。
- 类型名描述领域概念；文件名与主要导出保持可检索的对应关系。新增字段时搜索其默认值、读写方、文档和测试。

## 类型与函数

- 遵循仓库 strict TypeScript 配置。边界输入先校验，再收窄类型；避免用宽泛的 `any` 或类型断言掩盖不确定数据。
- 对有不同状态和字段要求的对象使用联合类型表达有效组合；避免多组布尔值允许互相矛盾的状态。
- 函数保持单一目的；有可复用价值且能独立验证的计算放入 `src/utils/`。DOM、存储和事件资源留在浏览器功能模块。
- 多个相关参数使用具名对象；函数只接收自己需要的数据，不读取不透明的全局上下文。
- 导出类型或跨模块接口要说明稳定含义；局部实现让 TypeScript 推导即可，不为每行代码重复注解。

## 注释

- 注释优先解释 WHY：设计取舍、外部约束、生命周期边界或容易误改的契约。
- 代码已经清楚表达的操作不再逐行复述。算法、复杂时序或外部组件限制才补必要的 HOW。
- 注释贴近代码并随实现更新；删除或修改逻辑时同步修正相关注释，避免保留旧方案说明。
