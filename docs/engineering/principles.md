# 项目原则

## 产品范围

- 项目是个人博客，优先服务文章写作、发现和阅读。新功能需要解决已经出现的阅读或维护问题。
- 根目录 README 面向 GitHub 访客，准确区分本站内容与 AstroPaper 主题来源。
- 保持 Astro 静态生成和 GitHub Pages 部署。正文、标题层级和主要导航应在生成 HTML 中存在；JavaScript 用于增强交互。
- 对当前规模保持适度实现：先使用现有浏览器能力和依赖；只有出现明确缺口且收益足够时才增加依赖或通用机制。
- 搜索使用已有 Pagefind 默认全文搜索。没有真实使用反馈前，不增加本项目自建的模糊匹配、排序或索引层。

## 内容与兼容

- `posts/` 是文章源。站点功能改动不顺带改写作者正文、标题、发布时间或标签。
- 维护已有 URL、锚点、GitHub Pages 基础路径和配置语义。确需变更时说明影响和迁移方式。
- 不为尚无内容或维护意愿的栏目建设完整功能；展示占位与已发布页面要明确区分。
- 优先复用现有设计 token、组件、工具和依赖，避免复制一份相同数据或状态。

## 变更范围

- 修改围绕明确的问题展开。避免无关格式化、批量重命名和顺手重写。
- 抽象用于消除已有重复或耦合；文件行数本身不是拆分理由。
- 优先简单、可读的职责边界和可验证的局部行为，不为假设中的未来需求预建框架。
