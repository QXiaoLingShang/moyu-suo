# 质量与交付

## 修改流程

1. 阅读本规范索引及相关功能说明，查看 `git status` 和目标差异，保留已有未提交内容。
2. 确认问题、行为边界和受影响接口，再做最小范围修改。
3. 对受影响的调用方、DOM 属性、CSS 选择器、语言键、配置和文档做全文搜索；跨层改动按各层规范复核。
4. 按改动风险运行相应检查，并如实说明未覆盖的行为。

## 仓库命令

使用 `pnpm` 和仓库现有锁文件，不混用包管理器。

| 命令 | 覆盖范围 |
| --- | --- |
| `pnpm lint` | ESLint 全仓检查 |
| `pnpm format:check` | Prettier 全仓格式检查 |
| `pnpm test` | 当前登记的纯逻辑/布局用例 |
| `pnpm build` | Astro 检查、静态构建、Pagefind 索引生成 |

逻辑变化检查边界输入；页面/样式/交互变化需在真实浏览器检查对应视口、主题、键盘和动态效果偏好。构建通过只说明静态构建成功，不等同于运行时或视觉验收。

## 文档与提交

- 功能约束放在对应功能目录或模块旁的局部说明中（如 README 或架构说明），并由工程规范索引链接；仓库通用规则放在 `docs/engineering/`；文章写作规则继续使用 `posts/_README.md`。
- 行为、配置、存储、事件或接口变化时同步更新对应文档。文档描述必须能在代码或验证记录中找到依据。
- 临时测试文章、截图和调试产物与正式内容分开；未经要求不删除用户文件。
- 用户要求提交时使用语义化提交，按单一目的分组，并在提交前检查暂存差异。
