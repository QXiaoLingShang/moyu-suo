# 前端约定

## Astro 页面与组件

- 页面和组件优先在 Astro frontmatter 中完成构建期取数、路由组合和配置选择；浏览器专属 API 放在客户端脚本中。
- 首次 HTML 应包含正文、标题层级、主要导航和可读的控件名称。客户端增强不能成为阅读内容可见的唯一途径。
- 使用原生链接、按钮、表单控件和标题结构；只有在原生语义不足时才补 ARIA。交互状态同步到 `aria-expanded`、`aria-pressed`、`disabled` 等合适属性。
- 可见文本就是控件名称时优先复用它；图标装饰标记为隐藏。需要键盘交互的自定义控件需处理焦点、Escape 和关闭后的焦点归还。
- 固定的界面文案（如导航、控件名称和状态提示）由 `src/i18n/lang/en.ts`、`src/i18n/lang/zh-CN.ts` 和 `src/i18n/types.ts` 管理，两种语言保持相同键结构。文章正文和 frontmatter 字段（如标题、描述、标签）保留在内容源；配置或内容数据派生的名称遵循各自的数据来源，需要翻译时通过对应数据模型或明确的翻译键处理，不复制进 UI 字典。
- `data-i18n` 会用字典值替换元素的 `textContent`，只标记纯文本节点容器；元素内有图标或其他子节点时，把标记放在专用文本子元素上。
- 站内路径和静态资源路径考虑 Astro `base` 与语言路由，使用项目已有路径工具，不硬编码部署根路径。

## 客户端脚本与生命周期

- 客户端代码遵循 Astro 静态 HTML 加交互增强的模式；只在交互收益明确时增加脚本。
- `ClientRouter` 页面切换期间，初始化应可重复调用；移除页面前取消旧页面的监听器、观察器、动画帧、计时器、滚动锁和临时 DOM。依据功能使用 `astro:before-swap`、`astro:after-swap` 或 `astro:page-load`，不要无理由重复绑定。
- 脚本若创建装饰层，需保证其不进入无障碍树且不拦截正文交互；动态内容仍需有可访问的名称和键盘路径。
- 同时考虑窄屏、宽屏、明暗主题、键盘操作、触摸输入和 `prefers-reduced-motion`。减少动态效果应有明确退化行为，而不是仅缩短动画。
- 事件回调只收集必要输入并调度工作。高频滚动或指针事件通过 `requestAnimationFrame` 合并；布局读取集中后再写样式，避免重复构建 DOM。

## 第三方 UI

- 复用已选依赖提供的最小能力，不在页面脚本里复制一套同类引擎。
- 第三方组件需要被页面管理时，明确初始化时机、已有实例检测、失败状态和页面离开后的清理；不要假定 Astro 页面脚本每次导航都会重新执行。
