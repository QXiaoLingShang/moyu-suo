# 导航与返回

`data/siteNavigation.ts` 是栏目数据来源。URL 仍保持现有地址，内容层级为“首页 → Blog → 标签 / 搜索 / 归档 → 具体标签”。Blog 的可见子栏目链接与 Header 使用同一份数据并遵循搜索、归档开关；面包屑是层级导航，不承担历史返回。

`navigationHistory.ts` 是文章返回来源的唯一所有者，在全站 Layout 中注册一次；是否显示 Go Back 不影响记录来源。Main、首页和搜索不写共享返回存储。搜索负责实时维护当前查询 URL；来源模块在文章链接点击时先捕获页面 URL 与坐标，再由路由事件作为兜底，避免准备期间的滚动或异步加载改变用户实际离开的视口位置。

- 导航到文章时，记录切换前的完整 URL、视口坐标和可用的 Astro 历史索引，写入目标条目的 `history.state["moyu:return"]`，保留路由器的其他字段。进入另一篇文章会记录实际上一页；刷新与前进/后退读取对应条目，不读取一个不断被覆盖的全局来源。
- 来源只接受当前站点 base 内的同源 URL。文章链接无来源、新标签直达或禁用 JavaScript 时，Go Back 的静态目标为 Blog，不猜测外站历史。
- 可验证的历史索引优先交由浏览器历史和 Astro 恢复位置，包括文章内增加锚点历史后的返回。`history.state.index` 是当前安装 Astro 的可选实现字段，只有有效且向后时使用；升级 Astro 需回归。不可用时使用公开 `navigate` 替换当前条目和保存的坐标，字体完成后按导航版本校验恢复，避免迟到的回调移动新页面。
- 站内章节锚点不交换文档，通过公开 navigate 的 state 选项将当前文章来源保留在新条目，不覆写路由器的索引。普通/修饰键点击保留链接语义，Ctrl/Meta 点击不强行调用历史。
- `navigate` 的 `info.restoreScroll` 为站内返回的定位标记；分页路由定位模块从全站 Layout 初始化，覆盖从文章刷新后首次返回分页的情况；分页遇到该标记或历史遍历时不强制滚到底部。其他目录访问也不强制到底部。

回归应覆盖：首页、文章/标签分页、搜索查询、文章到文章、锚点与刷新、原生前进后退、禁用存储、无来源和无 JS；验证 URL、内容、来源链接与位置同时正确。普通导航和分页均保留整体视图过渡，减少动态效果沿用 Astro 的退化行为。
